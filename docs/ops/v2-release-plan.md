## Critical path

There are **two independent clocks** — run them in parallel from day one. The schedule's true long pole is the legal/credential clock, which is entirely external/owner-driven; the engineering clock can reach `v1.0` (non-legal-tier) without it.

**The serial spine (engineering clock):**
1. **OWNER publish gate** (registry tokens + `@digitalharm` org + repo public) → **`v0.1` publish.** Nothing downstream compounds until names are claimed and the repo is readable — install strings, conformance vectors, the awesome-safety-tools PR, and every connector-consumes-published-package step all wait on this. Lowest-effort, highest-leverage, already-de-risked (all dry-runs green). **This is the single next action.**
2. **hashkit conformance + drift-gate (`v0.3`)** — the literal dependency root. `hashkit-match` pins it; `csam-shield`, `trainguard`, and the Bluesky hepa rule all match against its hashes. It is also the GTM trust artifact (our differentiation is "NCMEC-conformance-verified," not "better hashing"). Gated only by synthetic-corpus sign-off (no creds/counsel) → escalate that sign-off to clear immediately. **FP-guard + PDQ quality-gating must land WITH the matcher** — an FP routes innocent content toward report/preserve, so they are correctness requirements, not nice-to-haves.
3. **csam-shield ActionRule + registry refactor (`v0.4`) BEFORE any new detector.** The current closed `DetectorKind` union (`types.ts:30`, confirmed) is the exact fixed-orchestration shape HMA proved wrong; every new detector touches the union + dispatch, so wiring PhotoDNA/Cloudflare/Granite/Presidio first guarantees a second rewrite. **Refactor is a hard predecessor**, enforced in the same single-writer lane.
4. **Golden-path build-vs-wrap spec frozen (`v0.4`) → create-fightcsam (`v0.5`) → docs-MCP (`v0.9`).** One spec, three front-ends (wizard, CLI, MCP). The spec must be single-writer and merged before its consumers, and it can only stabilize *after* the refactor + the two connectors define the real shape — hence Phases 4–5 deliberately **trail** v0.4–v0.5.
5. **Per-package API freeze → third-party security review → 1.0 tag**, per package, serial within each package.

**The long pole (legal/credential clock — start NOW, runs alongside everything):** NCMEC ESP credentials + outside-counsel sign-off (funded by the Lantern outreach; $25K of the $250K ask is the counsel retainer). These gate **only `v2.0`** legal-tier GA and have the longest lead time. Kick off the Lantern outreach and `counsel-scope-brief.md` review immediately so they're ready when the ladder arrives.

**What runs in parallel:** the **FightCSAM site is the conversion surface for the #1 ICP's coding-agent persona and never blocks engine work** — `apps/fightsam-site` is a disjoint write surface, parallelizes freely, ships on cadence (0–1/v0.2, 2/v0.3, 3/v0.4, 4/v0.5, 5/v0.9, 6/v1.0). The Bluesky adapter, red-team pack, and Osprey/Coop connector are brand-new packages consuming *published* deps, so they parallelize once their dep (conformant matcher / refactored emitter / published promptshield) is merged. The four `v1-legal-infra` packages have no shared write files → 4 parallel sub-tracks at v0.5.
