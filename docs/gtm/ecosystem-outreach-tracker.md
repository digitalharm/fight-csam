## 0. ANTI-SPAM PROTOCOL (read first — every rule is a hard gate, not a guideline)

1. **DO NOT promote anything before `v0.1` publish makes every `install → quickstart` resolve from a clean machine.** No PRs, no ally notes, no registry promotion, no Meta/ROOST ask. A broken `cargo add` on a CSAM tool is worse than silence. This tracker is **pre-staging only** until then.

2. **The single highest-leverage move is ONE value-first PR into [`roostorg/awesome-safety-tools`](https://github.com/roostorg/awesome-safety-tools).** One precise, factual, no-superlatives PR — under the correct existing sections (Hash-Matching / Classification / Reporting), leading with *"conformance-tested against Meta PDQ · ships no hash list · Apache-2.0,"* crediting the upstreams already listed. This is opt-in, durable, spam-proof distribution and the entry ticket to everything else. **Do this before any individual outreach.** Everything below is secondary to it.

3. **Prefer a merged upstream PR over an email, always.** A gift PR is opt-in, durable, and the exact inverse of issue-spam. Where a row's value is "a working integration / a fix / a plugin," ship the PR; do not send a message *about* sending a PR.

4. **Batch size + cadence: ≤ 5 contacts per week, total, across all tiers.** Hand-written, individually relevant, one project at a time. This is a solo maintainer cap, not a per-tier cap. Outreach is **release-pegged in bursts**, never a continuous campaign.

5. **Channel preference (strict order): merged PR > GitHub Discussion > maintainer email / existing thread / DM > GitHub Issue (only if the repo invites contact via Issues and there is a genuine, specific item).** **Never open a cold GitHub Issue as outreach.** A "we recommend your tool / did we describe it right?" Issue on a stranger's tracker reads as spam.

6. **Lead with the value; the ask comes much later, if ever.** The default opener is *"we credit your tool and send you traffic — did we characterize your entry correctly?"* Reciprocal credit, not a request. No logo, quote, or the word "partner" without **written** sign-off. Mirror the directory's own *"inclusion is not an endorsement"* line.

7. **No-duplicate rule.** One contact per project, ever, until they reply. Check the gitignored ledger before sending. **Never re-contact a non-response; never re-contact an opt-out; never automate.** If a project spans multiple repos (e.g. Meta's ThreatExchange monorepo holds PDQ/TMK/vPDQ/HMA/python-threatexchange), that is **ONE org relationship = one contact**, not one per sub-tool.

8. **Hard caps on who is in scope.** Only the **24 "use"** + a **curated subset of "learn-from"** where there is genuine value to send. Everything else is do-not-contact.

9. **DO NOT CONTACT (absolute):**
   - All **13 out-of-scope** projects (see §4).
   - All **41 reference-only** projects (see §3) — many are anonymous / low-provenance dataset dumps; there is nothing to send them.
   - **Big-Tech in-house Trust & Safety teams.** We adopt their *open-source artifacts*; we do **not** run relationship/promo outreach at their T&S orgs. This covers Meta, Google/Jigsaw/DeepMind, Microsoft/Azure, NVIDIA, Roblox, Adobe, Intel, Bumble, OpenAI. The **only** permitted touch is a substantive **upstream PR/issue on a genuine, reproducible item** — never a "we recommend you" note. These rows are kept in the tables for accurate crediting and are flagged **`DO-NOT-SOLICIT`**.

10. **Meta is special: route through ROOST, never cold-ping Meta T&S.** Meta is upstream, our conformance source, and a ROOST co-founder. Engagement is limited to (a) high-quality upstream PRs/issues to `facebook/ThreatExchange` *only on genuine discrepancies*, and (b) at `v1.0`+, **one** low-key ask via the ROOST bridge. Never imply endorsement from a merged PR or directory adjacency.

11. **No over-claiming, ever — including in openers.** Never the word *"compliant."* Never *"beats Meta / beats PDQ."* Always *"conformance-tested / helps you take defensible, documented steps; consult counsel."* An over-claim in an outreach message is as damaging as the spam itself.

12. **Sequencing of the relationship engine:** ROOST first (awesome-safety-tools PR + community) → Bluesky/AT-Proto beachhead (via the merged hepa adapter) → the rest of the "use" allies → curated "learn-from," each only when a concrete artifact (credit, integration, plugin, fix) exists to lead with.
